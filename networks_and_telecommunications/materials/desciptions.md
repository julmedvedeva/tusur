Создан проект на базе микрофреймворка Flask. Структура каталога включает основной модуль app.py, каталог шаблонов
templates/, каталог статических файлов static/ (с подкаталогами uploads/ и generated/), виртуальное окружение venv и файл
зависимостей requirements.txt (Flask, Pillow, matplotlib, gunicorn, python-dotenv). Секретный ключ приложения (SECRET_KEY)
вынесен в переменные окружения и загружается модулем python-dotenv из файла .env.
Реализована форма загрузки изображения (templates/index.html), позволяющая выбрать файл в формате PNG/JPG/JPEG/BMP и задать
параметры отрисовки креста: ориентацию (вертикальный, горизонтальный либо оба направления одновременно), цвет линии посредством
элемента <input type="color"> и толщину линии в пикселях (числовое поле с ограничением диапазона 1–200).
Реализована защита формы от автоматической отправки при помощи капчи. При каждом GET-запросе к маршруту / функция
new_captcha генерирует случайный пример на сложение двух однозначных чисел и сохраняет правильный ответ в серверной сессии
(session["captcha_answer"]). При обработке формы (маршрут POST /process) введённое пользователем значение сравнивается с
ожидаемым ответом; в случае несовпадения либо отсутствия ответа в сессии пользователь перенаправляется обратно на форму с
флеш-сообщением об ошибке.
Обработка изображения реализована средствами библиотеки Pillow. Функция draw_cross приводит изображение к цветовой модели
RGB, вычисляет координаты центра и с помощью ImageDraw.rectangle отрисовывает один или два прямоугольника заданной толщины и
цвета, формирующих крест выбранной ориентации. Загруженные и обработанные изображения сохраняются на диск с уникальными именами
(на основе uuid4), что исключает конфликт файлов разных пользователей.
Построение гистограмм распределения значений каналов R/G/B реализовано функцией histogram_png_base64 средствами библиотеки
Matplotlib (бэкенд Agg, без графического дисплея). Изображение разбивается на три канала, для каждого строится гистограмма
распределения яркости (256 интервалов), после чего график кодируется в формат PNG в буфере памяти и представляется в виде
строки Base64 для последующего встраивания в HTML-страницу без сохранения промежуточных файлов на диск. Гистограммы строятся
отдельно для исходного и обработанного изображений.
Страница результата (templates/result.html) отображает исходное и итоговое изображения, а также соответствующие им
гистограммы, расположенные попарно в две колонки при помощи CSS flexbox-вёрстки.
Настроена система непрерывной интеграции средствами GitHub Actions (файл .github/workflows/ci.yml): при каждом push в ветки
web_services_course/main, а также при создании pull request в main, выполняется установка зависимостей проекта из
requirements.txt и проверка корректности импорта модуля app.py.
Настроен запуск приложения в производственном режиме через WSGI-сервер Gunicorn (файл Procfile: web: gunicorn app:app);
выполнено развёртывание приложения на VPS-сервере (описание процесса — см. раздел 7).
