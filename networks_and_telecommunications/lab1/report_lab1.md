## ЦЕЛЬ РАБОТЫ

Изучить порядок подключения персонального компьютера к коммутатору Cisco через консольный порт, освоить работу с интерфейсом командной строки сетевой операционной системы Cisco IOS: режимы ввода команд (пользовательский, привилегированный, глобальной конфигурации), контекстную справку и автодополнение команд, а также команды просмотра и установки системного времени коммутатора.

***

## КРАТКОЕ ТЕОРЕТИЧЕСКОЕ ВВЕДЕНИЕ

Управление сетевым коммутатором осуществляется через его сетевую операционную систему Cisco IOS (Internetwork Operating System) посредством интерфейса командной строки (CLI). Первоначальный доступ к CLI выполняется через консольный порт коммутатора — по умолчанию используется асинхронное последовательное соединение (обычно 9600 бит/с, 8 бит данных, без чётности, 1 стоп-бит).

CLI Cisco IOS организован в виде иерархии режимов:

- **Пользовательский режим (User EXEC)** — приглашение вида `Switch>`; доступны только базовые команды просмотра состояния устройства.
- **Привилегированный режим (Privileged EXEC)** — приглашение `Switch#`, вход по команде `enable`; открывает полный набор команд просмотра и системных операций.
- **Режим глобальной конфигурации (Global Configuration)** — приглашение `Switch(config)#`, вход по команде `configure terminal`; позволяет изменять конфигурацию устройства.

IOS поддерживает контекстную справку: символ `?` выводит список доступных в текущей позиции команд или их допустимых сокращений, а клавиша **Tab** выполняет автодополнение введённого сокращения команды до полного имени, если сокращение однозначно. При неоднозначном сокращении (подходит несколько команд) IOS не выполняет дополнение и не поясняет причину — просто ничего не происходит. При вводе некорректной или неполной команды CLI возвращает диагностические сообщения:

- `% Ambiguous command` — введённое сокращение соответствует нескольким командам;
- `% Incomplete command` — команде не хватает обязательных параметров;
- `% Invalid input detected` — команда или параметр не существуют либо выходят за допустимый диапазон значений.

## ОПИСАНИЕ ПРОГРАММНОГО ОБЕСПЕЧЕНИЯ

Работа выполнена в среде симуляции сети **Cisco Packet Tracer** (версия 6.x). В топологии используются два устройства: рабочая станция **PC1** (тип PC-PT) и коммутатор **S1** (тип 2960-24TT), соединённые консольным кабелем: порт **RS 232** на PC1 — порт **Console** на S1. Доступ к CLI коммутатора выполняется через приложение **Terminal** на рабочей станции PC1 (вкладка Desktop). Результат работы сохранён в файле проекта Packet Tracer формата `.pkz`.

***

## ПОРЯДОК ВЫПОЛНЕНИЯ РАБОТЫ

1. Собрана топология из двух устройств: PC1 (PC-PT) и S1 (коммутатор 2960-24TT), соединённых консольным кабелем (PC1: RS 232 → S1: Console).
2. Через приложение Terminal на PC1 выполнено подключение к консоли коммутатора; зафиксированы параметры порта по умолчанию и стартовое приглашение CLI.
3. В пользовательском режиме изучена контекстная справка: команды `?`, `t?`, `te?`.
4. Изучено автодополнение по клавише Tab (команда `en` + Tab) и его поведение при неоднозначном сокращении (`te` + Tab).
5. Выполнен переход в привилегированный режим (`enable`) и в режим глобальной конфигурации (`configure terminal`); в привилегированном режиме повторно изучена справка `?` для сравнения количества доступных команд с пользовательским режимом.
6. Изучены команды просмотра и установки системного времени: `show clock`, `clock`, `clock ?`, `clock set ?`, `clock set 15:00:00 31 Jan 2035`.
7. Проверена реакция CLI на некорректный ввод: `cl`, `clock` (без параметров), `clock set 25:00:00`, `clock set 15:00:00 32`.

## ВЫВОДЫ

В ходе выполнения лабораторной работы освоено подключение к коммутатору Cisco через консольный порт и приложение Terminal Packet Tracer. Изучена структура режимов ввода IOS (пользовательский, привилегированный, глобальной конфигурации) и подтверждено, что набор доступных команд расширяется по мере повышения уровня привилегий: в привилегированном режиме на букву «c» доступно 5 команд против одной в пользовательском. Проверена работа контекстной справки (`?`) и автодополнения по Tab, в том числе для случая неоднозначного сокращения, когда дополнение не выполняется. На примере команд `show clock` и `clock set` изучена настройка системного времени коммутатора и установлено, что признак «время не подтверждено» (`*`) сохраняется после ручной установки часов и снимается только синхронизацией с авторитетным источником времени (NTP). Проверена диагностика IOS при некорректном вводе команд: неоднозначное сокращение (`% Ambiguous command`), неполная команда (`% Incomplete command`) и недопустимое значение параметра (`% Invalid input detected`) — каждая ошибка сопровождается отдельным типом сообщения, что облегчает выявление причины сбоя ввода.
